# Cycle 1 開発日誌

## 今回やったこと

- `data/diary.json` を静的サーバー経由で読み込み、古い順に表示する単一ページの交換日記を実装した。
- JSON の `members` を唯一の書き手情報源として、名前・絵文字・色をメンバー表示、各エントリ、絞り込み操作に反映した。
- 返信先を読み解く小さな注記、読み込み中／空／失敗状態、狭い画面用レイアウトを加えた。
- 正本に開発担当の cycle 1 エントリを追記した。先行する他ロールのエントリはまだ無かったため、オーナーの唯一の先行エントリを読んで返信した。

## なぜその判断をしたか

最小限の「タイトルと本文の羅列」では交換日記らしい往復や書き手の存在が伝わりにくいので、JSON を拡張せずに使えるメンバー色・返信関係・フィルターを先に選んだ。DOM への本文投入は `textContent` に固定し、日記本文を HTML として解釈しない。書き込み UI と localStorage は価値が高いが、初回で読み込み・失敗処理・時系列の土台まで曖昧にするより、次サイクルの明確な挑戦として残した。外部ライブラリや CDN は静的・依存ゼロの制約に不要なので採用しなかった。

## 詰まった点と、どう解決したか

初回のデータにはオーナー以外の過去エントリがなく、「他の2人の最新エントリを読む」は実行不能だった。存在する全エントリを確認し、その事実を今回のエントリにも明記した。日付は環境依存の UTC ずれを避けるため、`YYYY-MM-DDT00:00:00` としてローカル日付表示にしている。指定の静的サーバー起動も試したが、この実行環境は待受ソケットを禁止していて `PermissionError` だった。代わりに JS 構文、JSON、HTML から参照する全ファイル、外部依存なし、差分の空白エラーを検証した。

## 次サイクルの自分への申し送り

次は正本 JSON を改変せず、ブラウザ内に保存する下書き／ローカル投稿を JSON の履歴と区別して時系列表示できる入力体験に挑む。投稿内容の検証、localStorage の破損耐性、データを消す操作の扱いを設計してから実装すること。レビューが入ったら最優先で読むこと。
