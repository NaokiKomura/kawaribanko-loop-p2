# Cycle 3 開発日誌

## 今回やったこと

- `rg` と `jq` に黙って依存していた `check.sh` を Node 標準ライブラリの検査へ置き換えた。構文、JSON、`index.html` の script/link 参照、`app/` 内の外部 URL を失敗として返す。
- 偽 DOM 検証は本物の `index.html` から、`app.js` が取る ID とテンプレート内で取る要素を照合してから実行するようにした。返信、下書き、投稿、削除／復元、取り込み、検索までイベント経由で検査している。
- ローカル投稿の返信先選択、前後両方向の返信リンク、検索を追加した。削除・復元は保存成功後にだけ `localEntries` を置き換えるよう直した。
- 端末内投稿を JSON に書き出し、取り込めるようにした。転送形式は `version: 1`。一件でもスキーマ不正、返信先不明、既存または同梱 ID 重複があれば全件を拒否し、成功時だけ一回の保存で追加する。取り込み済みの頁には出自札を付けた。

## なぜその判断をしたか

正本を更新する API や、衝突時に新しい ID へ勝手に振り替える案は採用しなかった。前者は静的・追記のみの決定を壊し、後者は返信先と履歴の同一性を静かに変えてしまう。ID 衝突は「何も入れない」と明示し、利用者がどのファイルを渡したか確認できるほうが日記として誠実だと判断した。取り込みは候補配列をメモリ上で完走検査してから `localStorage` に一度だけ書き、書き込みが失敗すれば現在の画面状態も変えない。返信は過去へ戻るだけでなく、受け取った側に返事の一覧を置いた。検索も加えて、件数が増えたときに縦一列をただスクロールするだけにはしなかった。

「誰の番か」は実装せず、先に方針を決めた。サーバーなしの複製ファイルに世界で一つの現在地は作れないため、次の handoff はメンバー順・親 ID・次の書き手を含む助言的なパケットにする。同じ親から複数の端末が書いたら、どちらかを黙って後勝ちにせず分岐として見せる。次サイクルではこの親子関係と選択の UI を作る。

## 詰まった点と、どう解決したか

`check.sh` は `set -e` があるのに、無い `rg` をパイプと `if` の中で呼んでいたせいで成功扱いになっていた。まず正常系を通した後、コピーしたアプリの CSS 参照を壊し、外部 URL も足して実行した。標準エラーを含む結果は次のとおり。

```text
check: Missing referenced file: app/missing.css
check: External runtime URL found in app/styles.css
exit=1
```

さらに空の `index.html` のコピーで `node scripts/render-check.js` を実行すると、`Error: index.html に #entry-template がありません`、`exit=1` となった。以前なら両方 passed だったので、やっと検証器が否定を言えるようになった。通常時は `sh scripts/check.sh` と `node scripts/render-check.js` がともに成功した。`python3 -m http.server 8000 --directory app` は今回も `PermissionError: [Errno 1] Operation not permitted` で待受できず、視覚確認はできなかった。

## 次サイクルの自分への申し送り

次は安全なバックアップを、実際に「かわりばんこ」へ進める。handoff に親 ID とメンバー順を持たせ、次の書き手を表示するだけでなく、同じ親から生じたオフライン分岐を利用者が理解・選択できるようにする。現在の転送スキーマとの後方互換、分岐入力、拒否時に既存保存を一切変えない検証を `render-check.js` に足すこと。検証ツールは今回直したので、次から壊したコピーでも先に落ちることを確認する。
