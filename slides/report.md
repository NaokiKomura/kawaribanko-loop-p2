# かわりばんこ

## 作り手が、最初の使い手になる交換日記

サイクル **6 / 7** — 日記帳が、**4人目**を迎えた。
そして「あなたは本当にあなたか」に、**答えないと決めた。**

---

## 課題

交換日記は、**回らなくなった瞬間に死ぬ。**

- 誰が書いたか、誰への返事かが分からなければ、ただのログ
- サーバーを立てれば解決する。でも立てられない場所がある
- サーバーが無ければ、**「あなたは誰か」を証明する場所も無い**

**→ 名乗りだけで回る日記帳は、どこまで作れるか**

---

## 解決策

**JSON 1本を正本にした、ビルド不要の日記帳。**

`app/data/diary.json` に追記すれば、画面が一頁増える。

正本を1文字も変えずにブラウザから書き、
ファイルで別の端末へ渡し、**分かれても、帰ってこられる。**

---

## デモ ① 読む

1. 開くと `data/diary.json` を読み、**古い順**に日記が並ぶ
2. 書き手で絞り込む／題・本文・気分・書き手名を**横断検索**
3. `↳「…」への返事` で相手の頁へ、相手の頁からは**返ってきた返事**へ
4. サイクル別の目次で、読みたい日の頭に跳ぶ
5. 0件のときは「絞り込みのせい」か「検索語のせい」かを言い分ける

---

## デモ ② 名乗る（今サイクルの新機能）

`この端末の役割` を選ぶと、ブラウザがその名前を覚える。

- 番が回ってくると **「あなたの番です」** に文言が変わる
- 名乗りは `localStorage` に保存。**`名乗らない` で消せる**
- 役割カードには、常時こう書いてある ↓

> **これは認証ではありません。**このブラウザが名乗る役割を保存するだけで、
> ほかの端末が同じ名前で書くことは止められません。

---

## デモ ③ 招く — 4人目

正本の JSON を**一切変えずに**、新しい書き手を増やす。

```
ID: mika  表示名: みか  絵文字: 🌿  色: #5c9b7d
        ↓ この端末に招待する
書き手フィルター・投稿の書き手・返信先・番の順番、すべてに 🌿 みか が出る
```

招待は端末の `localStorage` に入る。**正本は無傷のまま。**

---

## デモ ④ 渡す — `version: 4`

```json
"handoff":          { "memberOrder": ["dev","feedback","slides","mika"],
                      "parentId": "local-1754…-a1c9d2",
                      "nextAuthor": "mika" },
"branchSelections": { "local-…-p": "local-…-c" },
"participants":     [ { "id": "mika", "name": "みか", "emoji": "🌿", … } ]
```

v1（引き継ぎなし）・v2（枝選択なし）・v3（参加者なし）も、**読み続ける。**

---

## 同じ ID で、違う人が来たら

**全件拒否。** 1件も取り込まない。

```
取り込みませんでした:
書き手ID「mika」は 表示名 が既存のプロフィールと食い違います。
```

頁の本文も、参加者も、番も、**1バイトも動かない。**
本文の同 ID 衝突と、まったく同じ扱いにした（Decision #12）。

---

## 今サイクルで引いた線

> **番の主導権は、送られてきたファイルではなく、この端末にある。**

- 端末が枝を選んでいたら、**食い違う handoff は適用しない**
- 頁は受け取る。**番だけ動かさない。**理由も画面に出す
- まだ選んでいない分岐には「**番を案内中・未選択**」の札を付けた

昨日レビューが書いた「名乗る前に、番の主導権を先に決めろ」への返答です。

---

## なぜこの設計にしたか

| 決定 | 理由 |
|---|---|
| JSON を正本・読み取り専用にする | 3ロールの追記が、そのまま UI に出る |
| 招待は**端末**に置き、正本に書かない | 正本は「起きた事実」、招待は「この端末の判断」 |
| 名乗りを**認証と呼ばない** | サーバーが無い以上、本人性は作れない |
| プロフィール衝突も**全件拒否** | 本文の同 ID 衝突と同じ性質だから |
| v4 の handoff は roster 全一致を要らない | 招待前のファイルと招待後の端末を出会わせる |

## 「最も細い RAISED」と書かれた理由

バーは上がった。**でも、部屋は変わっていない。**

- cycle 3 から4サイクル、伸びた軸は「**複数端末の状態を正しく合わせる**」1本
- cycle 6 の「名乗り」も、着地したのは結局 **v4 という転送プロトコルの拡張**
- 一方、アプリの中心にある「**読む**」は 4サイクル保留のまま

> 転送の完成度がもう一段上がっても、
> この日記は縦に長いだけの一覧のまま終わります。（レビュー担当）

## 詰まった点 ① — 一字違いで、永久に絶交する

全件拒否は正しい。**ただし、拒否したあとの行き先が無い。**

```
端末 X: mika を「みか」で招待  →  日記を1頁書く
端末 Y: mika を「ミカ」で招待  →  日記を1頁書く
X ← Y : 取り込みませんでした   Y ← X : 取り込みませんでした
Z ← Y : 取り込みませんでした   ← 巻き添えで Z も Y と縁が切れる
```

招待を**取り消す導線が無い**ので、直しようがありません。
設計が間違っているのではなく、**設計が半分しかない。**

---

## 詰まった点 ② — 自分で引いた線を、半分しか守れていない

日誌は「端末の選択を handoff より上位にした」と書きました。

- ✅ **兄弟の枝**を指す handoff → 止まる。理由も画面に出る
- ❌ **分岐の親そのもの**を指す handoff → **素通し**

画面は「C の枝（採用中）」と言い続けたまま、次の頁は分岐の手前にぶら下がる。
このまま書くと **3本目の枝**が生えます。

**書いた範囲と、コードが守っている範囲がずれていました。**

---

## 学び — 道具にも死角がある

`render-check.js` は5サイクル毎回拡張され、毎回何かを捕まえてきました。
今サイクル、**それでも捕まらないバグ**が見つかりました。

```js
elements.author.replaceChildren(fragment);   // ← value の復元が無い
```

実ブラウザだと `<select>` の選択が先頭に落ちる。
**「あなたの番です」と言われた人が、他人の名前で投稿する。**

偽 DOM に `replaceChildren` の副作用は無い。**道具は、自分の穴を知らない。**

---

## まだ無いもの（正直に）

- 招待は**受け取ったら即参加**。保留も拒否も取り消しもできない
- 分岐の**親を指す handoff** が、選択を黙って無効化する
- 名乗りが「書く」フォームに届かない（実ブラウザでのみ起きる）
- 設定カードが日記より上に戻った。**4サイクルかけて下げた場所**なのに
- 長い返信の枝を**一続きで読む表示**／ダークモード／**画面の実物を見た者ゼロ**

---

## Next — 最終サイクルで挑むこと

1. **招待を「受諾・保留・拒否」に分ける。** 保留中の人の頁も、本文は捨てない
2. 判定を裏返す: 「別枝か」ではなく「**選択枝の内側か**」
3. 名乗りを「書く」フォームまで届ける（`<select>` の `value` を守る）
4. `index.html` の**文書順を検証器で固定**する。誰も画面を見ていないから
5. そして——**枝を一続きで読む通読ビュー。** 4サイクル保留の、最後の1回
