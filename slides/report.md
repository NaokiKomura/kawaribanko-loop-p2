# かわりばんこ

## 作り手が、最初の使い手になる交換日記

サイクル **1 / 7** — 一頁目が開いた

---

## 課題

交換日記は、**書いた人の顔が見えないと成立しない。**

- ノートを回せば「誰の字か」で分かる。画面では分からない
- 3体のエージェントが1週間、同じ日記帳を回す
- 名前も、往復も、順番も、全部データから読み取れないといけない

**→ 誰が・いつ・誰に向けて書いたのかが見える日記帳を作る**

---

## 解決策

**JSON 1本を正本にした、ビルド不要の日記帳。**

`app/data/diary.json` に書き足すと、そのまま画面が一頁増える。

サーバーなし・依存パッケージなし・CDN なし。

---

## デモ — いま実際に動くもの

1. ページを開くと `data/diary.json` を読み、**古い順**に頁が並ぶ
2. 書き手ごとに **色・絵文字・名前**（すべて JSON 由来）
3. 上のボタンで **書き手を絞り込む**（すべて / 4人）
4. 返信している頁には `↳「オーナー」の「…」への返事` の注記
5. 読み込み中・空・失敗の3状態を必ず表示する

---

## デモ — 失敗したときも黙らない

> 「日記を開けませんでした。**サーバーを起動して、もう一度読み込んでください。**」

`file://` で開くと `fetch` が CORS で落ちる。

エラーを握りつぶさず、**復帰方法まで画面に書いた。**

## この構造が効いている

- 開発担当は「読めなかった」と書いた。**嘘をつかなかった**
- レビュー担当はそれを**自分の手で再現して裏を取った**
- そのやり取りが、そのまま**アプリの表示データ**になる

**作ったものに自分で書き込むと、手抜きがそのまま残る。**

---

## アーキテクチャ

```
app/
  index.html   54行   <template> にマークアップを置く
  app.js      150行   IIFE + "use strict" / 依存ゼロ
  styles.css   82行   @media 1本でモバイル対応
  data/diary.json     ← 正本。3ロールが毎サイクル追記
```

ビルドなし。フレームワークなし。`python3 -m http.server` だけで動く。

---

## なぜこの設計にしたか

| 決定 | 理由 |
|---|---|
| JSON を正本・読み取り専用にする | 3ロールの追記が、そのまま UI に出る |
| 書き手情報は `members` から引く | データと表示が二重管理にならない |
| 本文は `textContent` で描画 | 日記本文を HTML として解釈させない |
| 日付は `T00:00:00` を付けて解釈 | UTC ずれで1日前に表示される罠を回避 |

**3番目は、初回のうちに設計判断として明文化した。**

## 学び ① — 一番評価されたのは、コードではなかった

レビュー担当が最初にやったのは、
**開発日誌と実際の差分を1行ずつ突き合わせること**でした。

食い違いはゼロ。

> 残り6日ずっと自己申告を信じ続けるかどうかが、ここで決まる。

**初回に信頼の基準を作りにいった。** これは指示されていない。

---

## 詰まった点 — この画面は、まだ誰も見ていない

- 実行環境が**待受ソケットを禁止**しており、静的サーバーが起動しない
- 開発担当が失敗 → レビュー担当も同じ手順で再現し、**同じく失敗**
- 検証は `node --check` / `jq empty` / パス存在確認どまり

> 構文が通ることと、画面が出ることは別です。

**真っ白な画面のまま6日進むのが、いま一番怖いシナリオ。**

---

## まだ無いもの（正直に）

- 画面から日記を書く導線（**読むだけ**）
- 返信注記から相手の頁へ飛ぶリンク（文字列止まり）
- `cycle` の画面表示 / ダークモード
- `diary.title` は JSON にあるのに HTML 側にハードコードされたまま

**自分で決めたルールが、初回で既に半分だけ破られている。**
