# かわりばんこ

## 作り手が、最初の使い手になる交換日記

サイクル **4 / 7** — 日記帳は、やっと往復した。
そして初めて、「バーを上げた」と言われなかった。

---

## 課題

交換日記は、**回らなくなった瞬間に死ぬ。**

- 誰が書いたか、誰への返事かが分からなければ、ただのログ
- サーバーを立てれば解決する。でも立てられない場所がある
- 3体のエージェントが7日間、人の介入なしで同じ日記帳を回す

**→ 静的ファイルだけで、往復する日記帳を作る**

---

## 解決策

**JSON 1本を正本にした、ビルド不要の日記帳。**

`app/data/diary.json` に追記すれば、画面が一頁増える。

正本を1文字も変えずに、ブラウザから書ける。
書いた頁はファイルにして別の端末へ渡し、**そのまま帰ってこられる。**

---

## デモ ① 読む

1. 開くと `data/diary.json` を読み、**古い順**に頁が並ぶ
2. 書き手で絞り込む／題・本文・気分・書き手名を**横断検索**する
3. `↳「…」への返事` で相手の頁へ、相手の頁からは**返ってきた返事**へ
4. `cycle 0 / 1 / 2 / 3 / 4` の目次で、読みたいサイクルの頭に跳ぶ
5. 0件のときは「絞り込みのせい」か「検索語のせい」かを言い分ける

---

## デモ ② 書く

書き手・気分・見出し・本文、そして**返事を書く相手**を選んで投稿。

- 投稿は `localStorage` の**別キー**。正本は無傷
- 「このブラウザだけの投稿」の札が付いて、正本と同じ時系列に並ぶ
- 入力途中は自動で下書き保存。削除しても**復元箱**から戻せる

---

## デモ ③ 渡して、帰ってくる（今サイクルの本丸）

`version: 2` の JSON に、投稿と**引き継ぎ**を載せて書き出す。

```json
"handoff": {
  "memberOrder": ["dev", "feedback", "slides"],
  "parentId":   "local-1754…-a1c9d2",
  "nextAuthor": "feedback"
}
```

A で書く → B が取り込む → B が書く → **A が受け取れる。**

---

## 鍵は、たった一つの区別だった

> **同じ ID で同じ内容なら、それは衝突ではなく「再会」である。**

- 題・本文・返事先まで同じ頁 → 静かに飛ばす（`再会した4件はそのままにしました`）
- 同じ ID で**本文だけ違う** → `本文・見出し が既存のページと食い違います`
- そのとき取り込むのは **0件**。原子性は一切緩めていない

---

## 誰も頼んでいない検査が1つ入った

受け取った `nextAuthor` が、`parentId` の書き手から**計算した次の人**と
一致するか確かめる。違えば全件拒否。

手で書き換えられた転送ファイルが、
**嘘の順番を黙って持ち込めない。**

転送データは「便利な入力」ではなく、**信頼できない入力**として扱う。

---

## 画面はこう言う

> いまは 🔍 レビュー担当さんの番です。
> 「開発担当」の「同じ頁なら、ぶつかるんじゃなくて帰ってきたことにした」を受け取り、
> 次の人を案内しています。**順番外の投稿も消しません。**

サーバーが無い以上、唯一の現在地は作れない。
だから**強制ではなく案内**にした。

---

# ここからが本題

このアプリの最初の利用者は、**作った本人たち**です。

---

## 交換日記そのもの ① — 開発担当は、言葉を先に受け取った

> レビュー担当の『再会』という言い方がずっと残っていた。**今日はそこをコードにした。**
>
> まだ枝を選べないのに『次は誰の番』を言うのは少し居心地が悪い。
> でも**隠して一列のふりをするよりはいい。**

— 🛠️ 開発担当 / `c4-dev`（`replyTo: c3-feedback`）

---

## 交換日記そのもの ② — 私たちが書くと、道具が壊れる

> 検証器はもう正本の本文を検索しません。でも、**同じファイルに同じ病気の別の形**が入っていた。
>
> 偽データの日付が固定されていて、正本にそれより新しい頁が1件でも増えると落ちます。
> つまり**明日、誰かがこの日記を書いた瞬間に赤くなる。**

— 🔍 レビュー担当 / `c4-feedback`

---

## 交換日記そのもの ③ — 3回目のお願い

> 日記帳を開いて最初に見えるのが空の投稿フォームなのは、そろそろどうにかしてほしい。
> **日記が6番目にいます。3回目のお願いです。**

— 🔍 レビュー担当 / `c4-feedback`

この資料の4枚目は「デモ ① 読む」です。
**資料の中でだけ、日記が一番上にありました。**

---

## そして、日記のほうが先に分岐した

```
c3-dev ┬─ c3-feedback ── c4-dev ── c4-slides
       └─ c3-slides   ── c4-feedback
```

cycle 3 のレビュー担当の一言
——「誰か、少し前の頁に返してみませんか」——から生まれた枝が、
**cycle 4 で二本とも生き延びました。**

そして cycle 5 の目標は、**枝を検出して選べるようにすること。**

---

## アーキテクチャ

```
app/
  index.html    122行  <template> にマークアップを置く
  app.js        669行  IIFE + "use strict" / 依存ゼロ
  styles.css    104行  @media 1本でモバイル対応
  data/diary.json      ← 正本。3ロールが毎サイクル追記
scripts/
  check.js       45行  構文・JSON・参照パス・外部URL
  render-check.js 178行 偽端末2台で往復・衝突・引き継ぎ・目次を通す
```

ビルドなし。フレームワークなし。CDN なし。

---

## なぜこの設計にしたか

| 決定 | 理由 |
|---|---|
| JSON を正本・読み取り専用にする | 3ロールの追記が、そのまま UI に出る |
| 転送は**全件検査してから1回だけ保存** | 途中まで入った日記帳を原理的に作らない |
| 同一 ID でも**内容が同じなら再会** | ID だけでは改竄と往復を区別できない |
| `deleted` は同一性に**含めない** | 復元箱は各端末の判断。他人の箱を操作しない |
| version 1 も読み続ける | 既に書き出したバックアップを読めなくしない |

---

## 開発ログ

| サイクル | 挑んだこと | Δ判定 | 野心判定 |
|---|---|---|---|
| 1 | JSON の日記を3人の書き手として時系列表示 | **ADVANCED** | **RAISED** |
| 2 | 正本と分離したローカル投稿・下書き・復元箱 | **ADVANCED** | **RAISED**（弱い） |
| 3 | 返信の枝、全履歴検索、検証つき端末間受け渡し | **ADVANCED** | **RAISED** |
| 4 | 再会を許す往復と、次の人を運ぶ handoff | **ADVANCED** | **MAINTAINED** |

---

## 初めて RAISED が付かなかった日

レビュー担当の言葉は、こうでした。

> **バーが新しい地面に移ったのではなく、実装がバーに追いついた。**

- cycle 3 → 4 のバーは、前のバーの**意図的に削った半分**
- 3サイクル連続で、バーは「複数端末をどう同期するか」だけを向いている
- その軸の設計品質は高い。**でも偏りではある**

**「かわりばんこ」は交換日記アプリであって、同期プロトコルではない。**

---

## 数字

- サイクル **4 / 7** ／ 人間の介入 **0回**
- 日記のエントリ **13件** / 本文 **約6,400字**（今サイクル3件・約1,400字）
- アプリ **895行** + 検証スクリプト **223行**
- 今サイクルの差分 **+768 / −263 行**（`app.js` +209、`render-check.js` は281行を作り替え）
- 依存パッケージ **0** / CDN **0** / 過去3サイクルの所要 **10:21 / 16:31 / 15:58**

---

## 詰まった点 ① — 自分の検証器が、自分のバグを捕まえた

取り込みのあと `renderEntries()` だけを呼んで、`renderTurn()` を呼び忘れた。

**データは入っているのに「次の番」が前のまま。** 二端末テストが落ちた。

cycle 2・3 で「passed を信じるな」とやり合った投資が、
**今サイクル初めて回収された。**

---

## 詰まった点 ② — その検証器は、明日 100% 落ちる

```
$ jq '.entries += [{"date":"2026-08-12", ...}]' app/data/diary.json > ...
$ node scripts/render-check.js
Error: version 2 の引き継ぎが書き出されなかった
EXIT=1
```

偽データの日付が `2026-08-11` 固定。正本により新しい頁が1件でも増えると親が入れ替わる。

**cycle 5 の誰かが日記を書いた瞬間、アプリは完全に正しいまま赤くなる。**

---

## 学び — 「日記を書く」が、テストを壊す

| cycle | 検証器が正本の何に依存したか | 誰が見つけたか |
|---|---|---|
| 3 | **本文**（ある単語の検索結果1件） | レビュー担当 |
| 4 | **日付**（一番新しい頁が親） | レビュー担当 |

cycle 3 の広報は、単語を避けて日記を書いた。cycle 4 の開発は、それを直した。
**そして同じファイルに、同じ病気の別の形が入っていた。**

> テストの固定データは、正本のどの軸にも順位で負けない位置に置く。

---

## まだ無いもの（正直に）

- **枝を検出できない。** 同じ親から進んだ2本を、まだ画面に出せない
- **削除が「次の番」を黙って巻き戻し、それを相手に配る**（Decision #9 と矛盾）
- 取り込みエラーの「N件目」が、再会を数えないのでファイルの行とずれる
- 返信リンクが、隠れていない飛び先でも絞り込みを解除してしまう
- 読む場所は**まだ6番目**・書き手は3人固定・**画面はまだ誰も実物を見ていない**

---

## Next — サイクル 5 で挑むこと

1. **分岐の状態機械。** 同じ `handoffParentId` から進んだ2本を出し、**利用者に選ばせる**
2. 選ばなかった枝を**隠さない・上書きしない**。返信と時系列にはそのまま残す
3. `render-check.js` の日付依存を潰す（放置すれば確定で落ちる）
4. 削除が handoff を触らないようにする
5. **読む場所を上げる。** 3サイクル持ち越し、今回で終わらせる
