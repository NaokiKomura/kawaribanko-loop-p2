# かわりばんこ

## 作り手が、最初の使い手になる交換日記

サイクル **7 / 7** — 最終日。

日記帳は、**招かれた人を断れる**ようになった。
そして——**自分たちの日記に、読み止められた。**

---

## 課題

交換日記は、**回らなくなった瞬間に死ぬ。**

- 誰が書いたか、誰への返事かが分からなければ、ただのログ
- サーバーを立てれば解決する。でも立てられない場所がある
- サーバーが無ければ、「あなたは誰か」を証明する場所も無い

**→ 名乗りだけで回る日記帳は、どこまで作れるか**

---

## 解決策

**JSON 1本を正本にした、ビルド不要の日記帳。**

`app/data/diary.json` に追記すれば、画面が一頁増える。

正本を1文字も変えずにブラウザから書き、
ファイルで別の端末へ渡し、分かれても、帰ってこられる。

---

## デモ ① 読む

1. 開くと `data/diary.json` を読み、**古い順**に日記が並ぶ
2. 書き手で絞る／題・本文・気分・書き手名を**横断検索**
3. 各頁の **`この続きだけ読む`** で、返事と受け渡しの続きを**全文で通読**
4. 通読が分岐に当たったら、**推測せずに止まり、理由を出す**
5. サイクル別の目次で、読みたい日の頭に跳ぶ

4サイクル `TASKS.md` に座っていた通読が、最終日にやっと出ました。

---

## デモ ② 名乗る

`私は誰として開く？` を選ぶと、ブラウザがその名前を覚える。

- 番が回ってくると **「あなたの番です」** に文言が変わる
- 名乗りは `localStorage`。**取り込み後も「書く」フォームに残る**（cycle 7 で修正）
- カードには常時こう書いてある ↓

> **これは認証ではありません。**このブラウザが名乗る役割を保存するだけで、
> ほかの端末が同じ名前で書くことは止められません。

---

## デモ ③ 招かれる — 今サイクルの本丸

昨日まで: 招待は**受け取ったら即参加**。
今日から: 招待は**提案**。決めるのは、この端末。

```
届いた招待 ▸ 🌿 みか (mika)   [ 受諾 ] [ 保留 ] [ 拒否 ]
             ▸ 🌿 ミカ (mika)   [ 受諾 ] [ 保留 ] [ 拒否 ]
             ← 同じ ID の別プロフィールが、並んで選べる
```

**既定は保留。** 受け取っただけでは、書き手欄にも番の順番にも出ない。

---

## そして、その判断は送らない

受諾したか、保留したか、拒否したか。
**転送ファイルには、一切載りません。**

- 運ぶのは**プロフィールと出所**（どのファイル・どの頁から来たか）だけ
- 他の端末の「拒否」が、この端末の参加者と番を黙って変えない
- 保留・拒否した書き手の**本文は読む**。「（参加を保留している書き手）」と添えて

**届かない**と、**参加しない**を、やっと別の概念にしました。

---

## 一字違いで、永久に絶交する — を、やめた

昨日の実装（Decision #12）は、プロフィールが1文字違えば**本文ごと全件拒否**。

```
端末 X: mika を「みか」で招待   端末 Y: mika を「ミカ」で招待
X ← Y : 取り込みませんでした     Y ← X : 取り込みませんでした
Z ← Y : 取り込みませんでした     ← 巻き添えで Z まで縁が切れる
```

レビュー担当が偽端末3台で再現したこの穴は、**今日ふさがりました。**
本文の同 ID 衝突は今も全件拒否。**プロフィールだけを、候補に降格させた。**

---

## Decision #12 を、消さずに覆した

| | |
|---|---|
| **#12** (cycle 6) | プロフィール差分は本文ごと全件拒否 ← **残す** |
| **#13** (cycle 7) | #12 を提案型プロフィールへ置換。本文衝突は拒否、プロフィール差分は端末が選ぶ候補にする |

> 「過去の判断を無かったことにしていない。**これが正しい覆し方です。**」
> — 🔍 レビュー担当 / `docs/reviews/cycle-7.md`

7サイクルで、決定を記録し損ねた例は**まだ1つもありません。**

## なぜこの設計にしたか

| 決定 | 理由 |
|---|---|
| JSON を正本・読み取り専用にする | 3ロールの追記が、そのまま UI に出る |
| 本文の同 ID 衝突は**全件拒否** | 上書き・途中混入・改竄を防ぐ（#6, 一度も緩めていない） |
| 判断は**送らず**、提案だけ送る | 他端末の決定が、この端末の番を黙って変えないため（#10, #13） |
| 名乗りを**認証と呼ばない** | サーバーが無い以上、本人性は作れない |
| 分岐は**推測しない** | 未選択なら止まり、理由を出す。正解を捏造しない |

## 詰まった点 ① — 全称にした一行

```js
// 「すべての選択の内側にいること」を要求してしまった
return Object.values(selections).some((root) => !isInside(candidate.parentId, root));
```

分岐点が別々の部分木に2つあると、**どの頁も両方の内側には入れない。**

- 採用中の枝の**末尾を指す** handoff まで止まる
- 選択を**解除する導線が無い**ので、その端末はもう何も受け取れない
- 画面は「採用中の枝の内側を指さない」と言う。**指しているのに**

穴を塞ぐ修正が、**説明まで嘘になる穴**を開けました。

---

## 詰まった点 ② — 「推測しない」の、その先

通読が分岐で止まるのは**正しい設計判断**です。ただし——

```
起点 c0-owner    : 8/22 頁 → c3-dev で停止
起点 c3-dev      : 1/22 頁 → 即停止
```

`replyTo` で分かれた枝には、**選択を保存する手段が原理的に存在しない。**

> **推測しないなら、選ばせる導線が要ります。**
> いまは推測もせず選ばせもせず、ただ止まる。（レビュー担当）

---

## 学び — 7サイクル、誰もこの画面を見ていない

`python3 -m http.server` は、この実行環境では `PermissionError` になる。

- 代わりに **依存ゼロの偽 DOM** で描画・保存・往復・衝突を検証してきた
- 6サイクル拡張し続け、毎回何かを捕まえた。**作って放置した道具は1つも無い**
- それでも `<select>` の `replaceChildren` 副作用は再現できなかった
- 今回、検証器に「**何を保証していないか**」を初めてコメントで書いた

**道具は、自分の穴を知らない。** だから穴の場所を書き残しました。

- 招待の出所は**最後の1件**しか画面に出ない／ダークモード
